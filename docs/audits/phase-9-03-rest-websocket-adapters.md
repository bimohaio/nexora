# Phase 9.03 — REST and WebSocket adapters audit

Status vocabulary: PASS, PARTIAL, FAIL, NOT_APPLICABLE.

| Requirement                                         | Status         | Evidence and remaining risk                                                                                                                                                                     |
| --------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Package ownership and dependency direction          | PASS           | Separate `datasource-rest` and `datasource-websocket` packages depend only on Core and datasource-core.                                                                                         |
| Transport abstraction                               | PASS           | Injectable HTTP transport and WebSocket factory; browser/Node-capable defaults are isolated.                                                                                                    |
| Credential boundary, endpoint validation, redaction | PASS           | Operation-time auth providers, scheme/host/credential checks, safe endpoints without queries. DNS/private-network enforcement remains a host responsibility.                                    |
| Header and payload safety                           | PASS           | Static secret headers rejected, CR/LF blocked, bounded requests/responses/messages/batches/queues.                                                                                              |
| Declarative mapping and normalization               | PASS           | Own-property paths reject prototype segments; both adapters use datasource-core normalization.                                                                                                  |
| REST contract, readiness lifecycle, grouped read    | PASS           | Shared lifecycle and one-response multi-point extraction with partial failures.                                                                                                                 |
| REST polling, overlap, sharing, cancellation        | PASS           | Shared subscription manager deduplicates compatible requests; fixed-delay loop has one request and abort propagation.                                                                           |
| REST write                                          | PASS           | Explicit configuration and permission; bounded JSON batch body; no optimistic runtime event.                                                                                                    |
| REST HTTP handling                                  | PARTIAL        | 2xx and typed access/transient status classification exist. Conditional requests and bounded `Retry-After` scheduling are deferred.                                                             |
| REST health check                                   | NOT_APPLICABLE | Readiness validates configuration/authentication; no health check configured in the public contract.                                                                                            |
| WebSocket lifecycle, stale generation, reconnect    | PASS           | One authoritative generation, shared reconnect, explicit-close suppression, restoration by subscription manager.                                                                                |
| WebSocket authentication                            | PASS           | Short-lived subprotocol provider; no token status or diagnostics.                                                                                                                               |
| WebSocket decoding, mapping, ordering, isolation    | PASS           | Sequential bounded text JSON queue; invalid items do not prevent later messages.                                                                                                                |
| WebSocket local/server subscriptions                | PASS           | Local filtering and declarative subscribe/unsubscribe command modes.                                                                                                                            |
| WebSocket acknowledgement/handshake                 | PARTIAL        | Native-open completion only; server acknowledgement and application handshake mappings are deferred.                                                                                            |
| WebSocket read/write                                | NOT_APPLICABLE | Capabilities are false and operations fail deterministically.                                                                                                                                   |
| WebSocket heartbeat/backpressure                    | PASS           | Shared scheduler heartbeat and bounded fail/reconnect queue policy.                                                                                                                             |
| Duplicate handling                                  | PARTIAL        | Sequence is preserved; source-specific duplicate rejection is intentionally not inferred.                                                                                                       |
| Disposal and cancellation                           | PASS           | Idempotent disposal clears timers, queues, subscriptions, requests, handlers, and sockets.                                                                                                      |
| Runtime bridge reuse and batching                   | PASS           | Both emit normalized events for the existing generic bridge; no runtime package dependency. Bridge scheduling batches rapid values.                                                             |
| Browser/Node compatibility                          | PASS           | Fetch/browser WebSocket defaults and injectable host transports.                                                                                                                                |
| Unit and integration tests                          | PASS           | Fake transport tests cover validation, grouped REST read/write, socket lifecycle, mapping, ordering, and subscription commands. Existing runtime bridge tests cover protocol-neutral ingestion. |
| End-to-end runtime tests                            | PARTIAL        | Generic bridge and adapters are independently tested; protocol-specific bridge fixtures are deferred.                                                                                           |
| Documentation                                       | PASS           | Package READMEs document semantics, security, examples, compatibility, and limits.                                                                                                              |
| Phase 9.04 readiness                                | PASS           | Independent normalized adapters and explicit transport seams are available; noted optional protocol features do not block the next adapter phase.                                               |
