# Documentation

This documentation system separates normative framework specifications from detailed
architecture, data contracts, conventions, decisions, phase plans, audits, and API
references.

## Start here

- [Master specification](master-spec/README.md) — project-wide source of truth.
- [Architecture](architecture/README.md) — subsystem design and runtime flows.
- [Data model](data-model/README.md) — persisted and renderer-facing contracts.
- [Conventions](conventions/README.md) — mandatory implementation conventions.
- [ADRs](adr/README.md) — numbered architectural decisions.
- [Phases](phases/README.md) — Phase 0–15 specifications.
- [Audits](audits/README.md) — historical conformance reports.
- [API](api/README.md) — implemented public contracts and future placeholders.
- [Roadmap](roadmap/README.md) — milestones, checklists, and release planning.

## Documentation authority

When documents differ, the order of authority is: master specification, accepted
ADR, current subsystem documentation, data-model or convention document, phase
specification, then historical audit. Implementation remains the final evidence of
what is currently available.
